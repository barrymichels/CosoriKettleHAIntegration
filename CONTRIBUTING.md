# Contributing

The Home Assistant component is in `custom_components/cosori_kettle/`. Its bundled `cosori_kettle_ble/` directory is also the source for the standalone Python package. Change the protocol in one place.

## Development environment

For the complete suite, use Python 3.14.2 or newer (required by Home Assistant 2026.9.4):

```bash
python3.14 -m venv venv
source venv/bin/activate
pip install -e '.[dev,test-ha]'
```

The `test-ha` extra pins the tested Home Assistant release, its Bluetooth dependencies, USB import dependencies, and the HA testing plugin. Hardware discovery/transport is mocked in tests; entity registration, config flows, and service dispatch use real Home Assistant code.

For library-only work, Python 3.11+ and `pip install -e '.[dev]'` suffice. The Home Assistant test module skips if Home Assistant or its testing plugin is absent.

## Checks

```bash
pytest
black --check custom_components tests
ruff check custom_components tests
MYPYPATH=custom_components/cosori_kettle mypy -p cosori_kettle_ble
mypy --python-version 3.14 custom_components/cosori_kettle
```

The explicit MyPy path checks all library modules under the library's own Python floor. The second command type-checks the Home Assistant layer against the interpreter Home Assistant 2026.9 requires. Protocol tests contain fixed reference packet bytes; avoid replacing them with packets generated by the implementation under test.

## Hardware validation

Automated tests cannot establish physical kettle or Bluetooth Proxy compatibility. Before declaring hardware support verified, perform the checks in [README.md](README.md): status, staged targets, boil/custom starts, stop, idle base removal, disconnect/recovery, and connection release.

To develop against a Home Assistant instance, link or copy `custom_components/cosori_kettle/` into its configuration's `custom_components/` directory and restart. Close other kettle BLE clients first.

## Protocol reference

Use the working [CosoriKettleBLE C++ component](https://github.com/barrymichels/CosoriKettleBLE/blob/main/components/cosori_kettle_ble/cosori_kettle_ble.cpp) as the reference. Its `PROTOCOL.md` has obsolete command/checksum descriptions; see [PROJECT_SUMMARY.md](PROJECT_SUMMARY.md) for the pinned comparison.

Include the concrete behavior changed and relevant automated/hardware test results in pull requests. Follow Black/Ruff formatting and keep public library APIs typed.
